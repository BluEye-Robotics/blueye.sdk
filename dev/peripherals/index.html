    Peripherals

    The Drone class maintains a list of peripherals that are attached to the drone. These peripherals can include cameras, grippers, and other devices that can be controlled using the drone's API.

    To list the peripherals that are currently attached to the drone, you can check the peripherals attribute of the Drone class. This attribute is a list of Peripheral objects.

    The SDK also has an attribute for each supported kind of peripheral (external_camera, external_light, gripper, laser, servo and skid_servo) to simplify access. If the drone carries two devices of the same kind, the attribute refers to the last one discovered; the full set is always in peripherals.

    Discovery

    Peripherals are discovered once per connection, from the first DroneInfoTel telemetry message in which the drone lists its guest ports and the devices on them. Until then, peripherals and get_guest_ports() return None and every peripheral attribute is None; a drone that has reported but has no guest ports gives empty lists. Devices plugged in or removed later in the session are not picked up until the next connect(). Disconnecting clears the lists and the attributes.

    if drone.laser is None:
    print("No scaling laser on this drone")
else:
    drone.laser.set_intensity(0.5)

    Every Peripheral records which port it sits on, the interfaces it requires from that port, and which ports on the drone fully support it. For detachable devices, get_detach_status() reports whether the device is currently attached.

    Guest ports

    To see the state of each guest port, including ports with nothing connected or with a connector fault, use get_guest_ports(). It returns one GuestPort per port the drone reports, or None if no guest port information has been received yet. A port either carries a list of devices or reports a connector error, never both; an empty port reports GUEST_PORT_ERROR_NOT_CONNECTED. Connector errors other than "not connected" are also logged as warnings when the ports are discovered.

    import blueye.protocol as bp

for port in drone.get_guest_ports():
    if port.error == bp.GuestPortError.GUEST_PORT_ERROR_NOT_CONNECTED:
        print(f"{port.number.name}: empty")
    elif port.error is not None:
        print(f"{port.number.name}: connector error {port.error.name}")
    else:
        names = ", ".join(device.name for device in port.devices)
        print(f"{port.number.name}: {names}")
    print(f"  provides {[cap.name for cap in port.capabilities]}")

    Navigation sensors

    The drone has no class for its navigation sensors yet; they appear in peripherals as plain Peripheral objects. What they provide decides which auto modes and mission instructions the drone will run:

    Device Provides
    DVL (Water Linked A50 or A100, Nortek Nucleus, Cerulean Tracker 650) Position for station keeping, weather vaning and waypoint missions. Altitude for auto altitude and seabed-relative depth set points.
    Blueye GNSS Position for the same, while the drone is at the surface with a fix.
    Ping sonar, mounted downwards Altitude for auto altitude and seabed-relative depth set points.
    UGPS, USBL, NMEA input over UDP Position for the map and for waypoint missions. The drone does not hold position on these, so station keeping and weather vaning need a DVL or the Blueye GNSS as well.

    PositionEstimateTel.position_estimate.navigation_sensors lists the position sensors the drone sees with an is_valid flag each, and get_altitude returns None while the altitude is not valid:

    import blueye.protocol as bp
from blueye.sdk import Drone

myDrone = Drone()

position = myDrone.telemetry.get(bp.PositionEstimateTel)
if position is not None:
    for sensor in position.position_estimate.navigation_sensors:
        print(f"{sensor.sensor_id.name}: {'valid' if sensor.is_valid else 'not valid'}")

print(f"Altitude: {myDrone.get_altitude()}")

    See the movement page for the auto modes and Mission planning for the instructions.

    External camera

    If the drone has a camera attached, the Drone class will have an external_camera attribute that is a GuestPortCamera object. This object can be used to control the camera.

    # Capture an image from the external camera
drone.external_camera.take_picture()

# Set bitrate for external camera to 2 Mbps
drone.external_camera.set_bitrate(2_000_000)

# Start recording video from the external camera
drone.external_camera.set_recording(True)

    External light

    If the drone has an external light attached, the Drone class will have an external_light attribute that is a GuestPortLight object. This object can be used to control the light.

    # Get the current intensity of the external light
intensity: float = drone.external_light.get_intensity()

# Set the intensity of the external light to 0.5
drone.external_light.set_intensity(0.5)

    Scaling laser

    If the drone has a scaling laser attached (the Blueye scaling laser, the Laser Tools Sea Beam or the Spot X laser scalers), the Drone class will have a laser attribute that is a Laser object. This object can be used to control the scaling laser. The dot spacing is 50 mm for the Blueye laser and 75 mm for the Sea Beam.

    # Get the current intensity of the scaling laser
intensity: float = drone.laser.get_intensity()

# Set the intensity of the scaling laser to 0.5
drone.laser.set_intensity(0.5)

    Laser dot tracking

    On the X3 Ultra and X7 the drone can track the laser dots in the main camera image. enable_tracking modulates the laser at 5 Hz, and the drone then reports the dot positions, their distance in pixels and the estimated distance to the subject in LaserTel. The drone overwrites the modulation flag with every intensity command, so set_intensity keeps the reported flag unless you pass modulated yourself. Tracking works on the full camera image, so enable_tracking(True) also resets the digital pan, tilt and zoom to 0, as the Blueye app does.

    drone.laser.enable_tracking(True)

detection = drone.laser.get_detection()  # blueye.protocol.LaserDetection, or None
if detection is not None and detection.detected:
    print(f"{detection.estimated_distance:.2f} m, dots {detection.pixel_distance:.0f} px apart")

# Or just the distance, None while the dots are not detected
print(drone.laser.get_estimated_distance())

drone.laser.enable_tracking(False)

    Gripper

    If the drone has a gripper attached, the Drone class will have a gripper attribute that is a Gripper object. This object can be used to control the grip and rotation of the gripper.

    If the connected gripper does not support rotation, the rotation velocity will be ignored.

    # Open the gripper
drone.gripper.set_grip_velocity(1.0)

# Close the gripper
drone.gripper.set_grip_velocity(-1.0)

# Rotate the gripper clockwise
drone.gripper.set_rotation_velocity(1.0)

# Rotate the gripper counterclockwise
drone.gripper.set_rotation_velocity(-1.0)

    Servo

    If the drone has a servo attached, the Drone class will either have a servo attribute that is a GenericServo object, or a skid_servo attribute that is a SkidServo object. These objects can be used to control the servo.

    servo is the Blueye generic servo. It takes a position between 0 and 1, where 0 and 1 are the end stops, since the drone has no idea what that is in degrees for the servo you have fitted. The drone drives generic servos on guest ports 1 to 3 only. The old set_angle and get_angle still work but warn, they map -90..90 degrees onto the 0..1 position.

    # Move to the middle
drone.servo.set_position(0.5)

# The reported position, and the position it is moving towards
drone.servo.get_position()
drone.servo.get_set_point()

    With two generic servos, drone.servo is the last one discovered. Each servo in drone.peripherals reports its own port, so pick by port_number when you have more than one:

    from blueye.sdk.guestport import GenericServo

servos = {p.port_number: p for p in drone.peripherals if isinstance(p, GenericServo)}

    skid_servo covers every multibeam tilt servo: the skid-mounted servo (first and second generation), which tilts ±28 degrees, and the head-mounted servo, which tilts ±45 degrees. The allowed range of the connected servo is in min_angle and max_angle.

    # Set the angle
drone.skid_servo.set_angle(20.0)

# Get the current angle, and the angle the servo is moving towards
drone.skid_servo.get_angle()
drone.skid_servo.get_set_point()

    Supported devices

    Device SDK class Attribute
    Blueye camera GuestPortCamera external_camera
    Blueye light, Blueye light pair, Blue Robotics Lumen GuestPortLight external_light
    Blue Robotics Newton (fixed and detachable), Blueprint Lab Reach Alpha Gripper gripper
    Blueye scaling laser, Laser Tools Sea Beam, Spot X laser scalers Laser laser
    Blueye generic servo GenericServo servo
    Blueye multibeam servo (V1 and V2), Blueye multibeam head servo SkidServo skid_servo

    Every other device the drone discovers (sonars, DVLs, GNSS, sensors, USB storage) is listed in peripherals as a plain Peripheral with its name, port and device ID, and its data is read from the matching telemetry messages through drone.telemetry.get().
